# Per-project queues for the report-export prototype

**Status: Chosen for the reversible prototype.** Use a separate worker queue for each project so that a large project's report exports can be scheduled independently of smaller projects. Production scheduling limits remain undecided.

## Context and alternatives

The current shared queue lets a large project delay smaller projects. The decision prioritises independent scheduling while accepting additional coordination between queues.

The viable alternatives were:

- **Shared FIFO queue:** least setup, but project contention remains.
- **Per-project queues:** independent scheduling, with additional coordination; chosen for the prototype.
- **Priority queue:** retains one queue, but requires an agreed priority policy.

## Implementation and validation

This record captures the choice; it does not establish implementation or performance success. Load tests have not run.
